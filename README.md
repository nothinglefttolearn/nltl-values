Shared static values for nltl repos: color and font tokens and named shapes (XY point sets), with thin loaders for Go and Python and a generated CSS file for websites.

This repo is the single source of truth. Change a value here, tag a release, and bump the pin in each consumer. Do not keep local copies in other repos.

**In scope:** static, versioned constants (colors, fonts, shapes, and similar).
**Out of scope:** per-environment config such as URLs, secrets, and feature flags, and the layout details of a single site or tool (widths, spacing, font sizes, corner radius, transition timings), which stay in that project.

## What's inside

| Path | Contents |
| --- | --- |
| `tokens/colors.tokens.json` | Colors in [W3C Design Tokens (DTCG)](https://www.designtokens.org/tr/drafts/format/) format |
| `tokens/fonts.tokens.json` | Font stacks, same format |
| `css/nltl-values.css` | Brand and web colors and every font as CSS custom properties, generated by `scripts/build-css` |
| `shapes/<name>.json` | One shape per file, e.g. `shapes/face.json` |
| `schema/` | JSON Schemas for both |
| `scripts/validate` | Validates everything; CI runs it on every push and PR |
| `go/` | Go package (data embedded with `go:embed`) |
| `python/` | Python package (data shipped as package data) |

### Colors

Tokens can sit at the top level or nest in groups. A token's path is its group names and its own name joined with dots:

```json
{ "primary": { "$value": "#DFA4E3", "$type": "color" }, "text": { "muted": { "$value": "#666666", "$type": "color" } } }
```

`primary` → `#DFA4E3`, `text.muted` → `#666666`. Values are `#rrggbb` or `#rrggbbaa`. `$description` is allowed on tokens and groups.

A value can instead be an alias: another token's path in braces. The loaders return the hex it points at, so the value is only stored once:

```json
{ "accent": { "$value": "{brand.secondary}", "$type": "color" } }
```

Colors are split into three top-level groups:

- **`brand`:** `brand.primary`, `brand.secondary`. Shared by websites and artwork; alias them from the other groups rather than copying the hex.
- **`web`** (website interface): `web.bg`, `web.bg-raised`, `web.bg-raised-2`, `web.fg`, `web.muted`, `web.border`, `web.border-strong`, `web.border-row`, `web.border-dashed`, `web.accent` (an alias of `brand.secondary`), `web.accent-hover`, `web.accent-fg`, `web.accent-glow`, `web.danger`, `web.danger-hover`, `web.danger-glow`, `web.success`, `web.warning`.
- **`art`:** the palette for image generation and animation projects. Empty for now.

In CSS, `brand` and `web` colors drop their group prefix, so `web.bg-raised` is `--bg-raised` and `brand.primary` is `--primary`. `art` colors are not in the CSS file. A name may therefore not appear in both `brand` and `web`; `scripts/build-css` fails if it does.

### Fonts

Each font token is a font stack: family names, most preferred first, ending with a generic family.

```json
{ "sans": { "$value": ["Helvetica Neue", "Arial", "sans-serif"], "$type": "fontFamily" } }
```

There are two: `sans` (body text) and `mono` (labels, buttons, metadata, the wordmark). In CSS they are `--font-sans` and `--font-mono`.

### Shapes

```json
{
  "$schema": "../schema/shape.schema.json",
  "name": "face",
  "description": "NLTL face. Left-aligned, 3/4 of the square's width, full height.",
  "points": [[0, 0], [0.75, 0.25], [0.75, 1], [0, 1]]
}
```

- `name` (required) uses lowercase letters, digits, and hyphens. It must be unique and match the file name (`shapes/face.json` → `"face"`).
- `points` (required) are `[x, y]` number pairs, in drawing order.
- `description` (optional) says what the shape is.
- `closed` (optional, default `true`): the last point joins back to the first, making a polygon. Set `"closed": false` for an open line. A closed shape needs at least 3 points and an open one at least 2.
- `$schema` (optional) points editors at the schema for autocomplete and inline errors. The loaders ignore it.
- Coordinates use screen orientation: the origin `(0, 0)` is the top-left, x increases to the right and **y increases downward**, as in SVG, HTML canvas and most image libraries. If you draw in a y-up system (e.g. matplotlib's default axes), flip y: `y' = height - y`.
- Coordinates have no unit. Each consumer decides how to scale them.

## Consuming

Pin to a release tag. Never depend on `main`.

**Go**

```sh
go get github.com/nothinglefttolearn/nltl-values@v0.1.0
```

```go
import values "github.com/nothinglefttolearn/nltl-values/go"

hex, err := values.Color("brand.primary") // "#DFA4E3"
hex, err = values.Color("web.accent")       // "#879B87", the alias resolved
stack, err := values.Font("sans")           // []string{"Helvetica Neue", ..., "sans-serif"}
face, err := values.Shape("face")           // face.Points[0].X, .Y
all, err := values.Colors()                 // map[path]hex
fonts, err := values.Fonts()                // map[path][]string
names, err := values.ShapeNames()
```

The raw files are also available as an `embed.FS` at `nltlvalues.FS` (import `github.com/nothinglefttolearn/nltl-values`).

**Python** (3.9+, no runtime dependencies)

```sh
pip install "nltl-values @ git+https://github.com/nothinglefttolearn/nltl-values@v0.1.0"
```

```python
import nltl_values

nltl_values.color("brand.primary")   # "#DFA4E3"
nltl_values.color("web.accent")      # "#879B87", the alias resolved
nltl_values.font("sans")             # ("Helvetica Neue", ..., "sans-serif")
nltl_values.shape("face").points     # ((0.0, 0.0), (0.75, 0.25), ...)
nltl_values.colors()                 # {path: hex}
nltl_values.fonts()                  # {path: (family, ...)}
nltl_values.shape_names()
```

Unknown names raise `KeyError` in Python and return an error in Go.

**CSS**

`css/nltl-values.css` puts every brand and web color, and every font, on `:root`. Load it at a pinned tag, then use the variables:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/nothinglefttolearn/nltl-values@v0.2.0/css/nltl-values.css">
```

```css
body { background: var(--bg); color: var(--fg); font-family: var(--font-sans); }
```

The file is generated: change the JSON, run `scripts/build-css`, and commit both. CI fails if they disagree.

## Versioning

Releases are git tags `vX.Y.Z` ([semver](https://semver.org)). The tag is the version for every language.

- **Patch:** a value changes without changing meaning, e.g. a color tweak or a shape that was redrawn.
- **Minor:** something is added, e.g. a new token, a new shape, or a new accessor.
- **Major:** something is removed or renamed, or a file format or API changes. Consumer code may break.

### Releasing

1. Merge changes to `main` with CI green.
2. Set `__version__` in `python/nltl_values/__init__.py` to the new version.
3. `git tag vX.Y.Z && git push origin vX.Y.Z`

## Developing

```sh
scripts/validate                         # needs uv; or: pip install jsonschema && python3 scripts/validate
scripts/build-css                        # regenerate css/nltl-values.css after changing tokens
go test ./...
uv venv && uv pip install . && .venv/bin/python -m unittest discover -s python/tests
```

To add a value, edit or add the JSON, run `scripts/validate` and `scripts/build-css`, and open a PR. The loaders read every file in `shapes/` automatically, so a new shape needs no code change.
